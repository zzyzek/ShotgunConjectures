# Reflective polynomial identity checker

**Method.** Polynomials over ℤ are `RPI.Poly := List (List Nat × Int)` (exponent vector, coefficient),
sorted by lexicographic exponent order. `RPI.check fs gs t` computes `Σ fs_i * gs_i` with a sorted
merge-add and a term-by-term multiply (structural recursion, `Bool` primitives `Nat.beq`, `Nat.blt`)
and compares the result with `t` term by term. `RPI.check_eval` (soundness) says that `check = true`
implies `Σ fs_i(x) gs_i(x) = t(x)` at every point `x` of every commutative ring; `RPI.check_zero` turns
it into ideal membership (all `fs_i` vanish at `x`, so `t` does). The proofs never use the ordering, so
an unsorted input can only make `check` fail. Each identity is one `decide +kernel` call; the kernel
evaluates `check` with GMP-backed `Nat` arithmetic, and no `ring` normalisation happens in the
elaborator. Rational certificates are scaled to integers first (`den * target = Σ g_i f_i`).

Large data (cofactors) enter through the `rpi% "e,e,..:c;..."` elaborator, which builds the
`List` term directly with raw `Nat` literals. This avoids numeral elaboration (a 200-term list
literal written as Lean syntax hit the 200 000 heartbeat limit). The elaborator is not trusted:
the kernel type-checks the resulting definition and evaluates `check` on it.

The small hypothesis polynomials (here Q(x_i), H_i(x_i), b_i) are written as ordinary Lean
literals so that `simp only [RPI.Poly.eval, RPI.Mono.eval]` plus `linear_combination` connects
them with the readable hypotheses; large polynomials (resultant factors S_i) are only used through
`RPI.Poly.eval`, never expanded.

**Measured (2026-11-05, 6 GB cap, one file).** Casas-Alvero
degree 6 with case split (784 KB, `casas_alvero6_reflective_mathlib.lean`): 62–72 s (linear_combination: 212 s). Unsplit (2.5 MB, 970-digit
coefficients): 60 s (linear_combination: exit 137 at 6 GB). Degrees 2–5: 10–30 s. See
core-ring-certificate-cost and core-kernel-certificate-throughput in methods/cores.jsonl.

**Pitfalls.** Use `decide +kernel`, not `decide` or `rfl` (the elaborator's `whnf` would evaluate the
checker first). Put the short factor first in `RPI.mul` (cost is one merge per term of the first
factor). Keep exponent vectors the same length within one identity (the order is then a monomial
order and products stay sorted). The theorem-name grep of tools/leancheck-mathlib.sh needs the
`RPI` namespace opened at the end of the file (`open RPI`), since the checker's theorems are printed
by short name.
