# Proof methods

The methods that settled the problems in this repository, each stated in a general form so it can be
recognised on a new problem. One directory per method; its `README.md` starts with a YAML front matter
block (between `---` lines) for programs, followed by the same content for people:

| field | meaning |
|---|---|
| `id` | slug, also the directory name and the tag used in `problems.jsonl` (`"methods"`, primary first) |
| `name` | human name |
| `role` | `disproof`, `proof`, `both`, `reading` (about the statement, not the mathematics) or `certification` |
| `cue` | how a problem looks when the method applies |
| `code` | library functions in [`oplib/`](oplib/) (paths from the repository root) |
| `lean_example` | a Lean file that uses the pattern |
| `worked_example` | a problem directory to copy from |

The body has **When it applies**, **Method**, **Certificate** (what a finished answer contains),
**Pitfalls**, **Code**, **Worked example**, and a generated list of the problems settled with the method.
`methods.json` lists the same fields as JSON.

Tags were assigned by reading each problem README (two agents, then a keyword pass adding
`complete-table-scan` where a published table is read). A problem can carry up to four tags.

`oplib/` is the Python library behind the methods (needs `sympy` and `python-sat`); `tests/run.py`
reproduces known results with it: `python3 -I methods/tests/run.py`.
